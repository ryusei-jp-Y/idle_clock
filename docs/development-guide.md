# 開発・学習ガイド

## 目的

開発速度を維持しながら、Flutter / Dart、設計、テスト、Git、デバッグを自分で説明・修正できる状態を目指す。

## 進め方

各機能を次のサイクルで開発する。

1. 実現したい振る舞いと完了条件を言葉で決める
2. 関連するFlutter / Dartの概念を短く確認する
3. AIが小さな差分で実装する
4. 差分を読み、ファイルとクラスの責務を確認する
5. テストと実機確認を行う
6. 学習者が最低1か所を自分で変更する
7. 判断理由や学びを短く記録する

## AIへ依頼する際のルール

- 実装前に「何を、なぜ変更するか」を説明する
- 一度に大きな機能を作らず、レビュー可能な単位に分ける
- 新しいDart構文やFlutter APIには短い説明を付ける
- エラーを隠すための場当たり的な修正をしない
- パッケージ追加時は、標準機能では不足する理由を説明する
- コード生成後にAnalyze、Test、Formatを実行する

## 最初に学ぶ項目

### Dart

- `final`と`const`
- Null safety
- class、constructor、method
- enum
- List / Map
- Future / async / await
- Streamの基本

### Flutter

- Widgetツリー
- `StatelessWidget`と`StatefulWidget`
- BuildContext
- レイアウト制約
- Stateと再描画
- AnimationController / Ticker
- CustomPainter
- アプリライフサイクル
- Widget testとunit test

## 最初の実装で担当する練習

- 時計の文字色を追加する
- 12時間 / 24時間表記のテストケースを1つ追加する
- 設定項目のラベルを変更する
- 反射速度の定数を調整し、変更結果を説明する

## レビュー時の確認事項

- このファイルの責務は何か
- Stateはどこが所有しているか
- 何がWidgetの再描画を起こすか
- 端末サイズや向きが変わるとどうなるか
- バックグラウンド移行時に何が止まるか
- 失敗する可能性と、それを確認するテストは何か

## Git運用

- 1コミットにつき1つの目的にする
- コミット前に差分を読む
- `main`を常に動作可能な状態に保つ
- 機能開発は短命なブランチで行う
- 生成物、秘密情報、署名ファイルをコミットしない

## 完了の定義

機能は、コードを書いただけでは完了としない。

- 完了条件を満たしている
- 自動テストまたは明確な手動確認手順がある
- Analyze、Test、Formatが成功する
- iOS SimulatorまたはiPhone実機で確認されている
- 実装の責務と主要な処理を説明できる
