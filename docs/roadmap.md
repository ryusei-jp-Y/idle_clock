# 開発ロードマップ

日数は学習時間を含む目安。各フェーズは、完了条件を満たしてから次へ進む。

## フェーズ0: 企画と方針の確定

**状態:** 完了

### 作業

- MVPと対象プラットフォームを確定する
- 技術構成をFlutterに決定する
- 画面構成と対象外機能を明文化する
- 仮プロジェクト名を決める

### 完了条件

- 企画書とロードマップがリポジトリに存在する
- MVPで作らない機能が明確になっている

## フェーズ1: 開発環境構築

**目安:** 1〜2日

**状態:** 完了

### 作業

1. Xcodeをインストールして初期設定を行う
2. Flutter stable SDKをインストールする
3. Android StudioでAndroid SDKとエミュレーターを設定する
4. VS CodeへFlutter / Dart拡張を追加する
5. `flutter doctor`の必須項目を解消する
6. Flutterプロジェクトを生成する
7. iOS SimulatorとAndroid Emulatorで初期画面を起動する
8. Gitリポジトリを初期化し、最初のコミットを作る

### 完了条件

- `flutter doctor`でiOS / Android開発に必要な重大エラーがない
- iOS SimulatorとAndroid Emulatorの両方でアプリが起動する
- `flutter analyze`と`flutter test`が成功する

## フェーズ2: 技術プロトタイプ

**目安:** 2〜4日

**状態:** 進行中

### 作業

- [x] 1秒ごとに正確に更新される時計を表示する
- [x] 1つの独自図形を画面端で反射させる
- [x] 縦横回転時に位置と軌道を補正する
- 衝突時にSEを再生する
- メイン画面表示中の常時点灯を実装する
- [x] バックグラウンド移行時にアニメーションを止める
- 実機でFPS、発熱、電池消費を確認する

### 完了条件

- 30分以上連続動作して破綻しない
- 画面回転、復帰、サイズ変更で図形が画面外に残らない
- 時計の更新とアニメーションが互いに不要な再描画を起こさない

### 判断ポイント

- 標準描画APIで性能が十分か
- 常時点灯時の発熱と消費電力を許容できるか
- SEをMVPに残すか

## フェーズ3: MVP設計

**目安:** 1〜2日

### 作業

- Widget、状態、描画、設定保存の責務を分ける
- `AppSettings`の型を定義する
- 画面遷移と設定UIのワイヤーフレームを作る
- テスト対象を決める
- 最低対応OSを決定する

### 完了条件

- 実装単位と依存関係が説明できる
- 時計計算、反射計算、設定保存を単体テストできる設計になっている

## フェーズ4: MVP実装

**目安:** 5〜10日

### 実装順

1. アプリテーマとメイン画面
2. 時計表示
3. バウンスアニメーション
4. アプリライフサイクルと常時点灯
5. 設定画面
6. 設定の端末内保存
7. 時計・ビジュアルのバリエーション
8. SE
9. 縦画面・横画面の調整

### 完了条件

- 企画書に記載したMVP機能が実機で動作する
- 主要ロジックに自動テストがある
- Analyze、Test、Formatのチェックが成功する

## フェーズ5: 品質改善

**目安:** 3〜5日

### 作業

- 複数サイズのiPhone / Android端末で表示確認する
- 長時間稼働時のメモリ、発熱、電池消費を測定する
- ライフサイクル、着信・通知、画面回転からの復帰を確認する
- コントラストと文字サイズを確認する
- クラッシュ、ログ、不要権限を確認する

### 完了条件

- リリースを妨げる既知の不具合がない
- 対象端末で長時間表示を許容できる
- プライバシー情報と利用権限を説明できる

## フェーズ6: テスト配布

**目安:** 3〜7日

### 作業

- Apple / Googleの開発者アカウントを準備する
- Bundle ID / Application IDを確定する
- アイコン、スクリーンショット、説明文を作成する
- TestFlightとGoogle Play内部テストへ配布する
- 少人数の試用フィードバックを収集する

### 判断ポイント

- 正式名称
- 価格、広告、課金の有無
- SEと常時点灯の初期設定
- ストア公開対象国

## フェーズ7: v1.0公開

### 作業

- テスト配布の問題を修正する
- App Store / Google Playの審査へ提出する
- 公開後のクラッシュとレビューを確認する

### 完了条件

- iOS / Androidのストアからインストールできる
- v1.1候補を、利用者の反応と技術的負債から選定できる

## フェーズ8: macOS対応

モバイル版の体験と内部設計が安定した後に着手する。

### 作業

- ウィンドウサイズ変更への対応
- メニューバー、フルスクリーン、キーボード操作の検討
- macOSでの常時点灯と省電力動作の確認
- Mac App Storeまたは直接配布の方針決定
