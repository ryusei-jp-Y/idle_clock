## 1. アプリ概要・目的

### 1-1. アプリの概要

現在時刻と、画面内を動き続けるビジュアルを組み合わせた時計アプリ。昔のDVDスクリーンセイバーを思わせる反射運動によって、「見ていて飽きない」「ぼんやり眺めていたい」体験を提供する。

### 1-2. 解決したい課題・背景

- 無になりたい時間や、画面をぼんやり眺める時間を少し楽しくする
- 懐かしい画面端の反射アニメーションをスマートフォンで手軽に楽しめるようにする
- 時刻確認という実用性と、アンビエントな鑑賞体験を両立する

### 1-3. 想定ターゲットユーザー

MVPでは、次のユーザーを主対象と仮定する。プロトタイプの試用結果をもとに見直す。

- 作業机やベッドサイドにスマートフォンを置き、時計として使いたい人
- レトロなスクリーンセイバーやミニマルな映像表現が好きな人
- 集中の合間や就寝前に、操作せず眺められるコンテンツを求める人

## 2. MVP機能

| 優先度 | 機能 | MVPでの範囲 |
|---|---|---|
| 高 | 時計表示 | 現在時刻、12/24時間表記、秒表示の切り替え |
| 高 | バウンスアニメーション | 独自図形が画面端で反射し、連続して動く |
| 高 | 常時点灯 | メイン画面の表示中は端末をスリープさせない |
| 中 | 時計バリエーション | 2〜3種類のフォント・レイアウト |
| 中 | SE | 画面端への衝突音のオン・オフと音量配慮 |
| 中 | 設定保存 | 選択内容を端末内へ保存 |
| 低 | ビジュアルバリエーション | 色・図形・軌跡など2〜3種類 |

### MVP対象外

- アカウント、認証、クラウド同期
- 課金、広告
- ソーシャル機能
- 外部APIやサーバー
- Windows / Linux対応
- 大量の物理パーティクル

| 画面 | 主な表示・操作 |
|---|---|
| メイン画面 | 時計、バウンスアニメーション、設定画面への導線 |

## 4. 技術スタック

### アプリ

- Flutter（stable channel）
- Dart
- Flutter標準の描画APIを優先し、必要になった時点で追加ライブラリを検討

### データ保存

- MVPは端末内の設定保存のみ
- 設定値は型を持つ単純なモデルとして管理
- バックエンド、API、外部データベースは使用しない

### 対象OS

- MVP: iOS / Android
- 次期対応: macOS

## 5. データモデル概要

`AppSettings`として以下を管理する。

- 12時間 / 24時間表記
- 秒表示の有無
- 時計スタイル
- ビジュアルスタイル
- SEの有無
- SE音量

## 6. 非機能要件・制約

### 基本方針

- 認証・認可は不要
- 初期言語は日本語。時刻表示は端末ロケールを考慮する
- 個人情報を収集しない
- DVDの名称・ロゴ・既存デザインをアプリ素材として使用しない
- メイン画面表示中は常時点灯とする

### アクセシビリティ

- 時計と背景の十分なコントラストを確保する
- SEに依存せず動作が理解できるようにする
- OSの「視差効果を減らす」などを考慮した代替表示を検討する

### パフォーマンス

- 対象実機で滑らかな表示を維持する
- 不要な画面全体の再描画を避ける
- 発熱とバッテリー消費を実機計測する
- アプリがバックグラウンドの間は描画・SEを停止する

## 7. デザイン・UI方針

- 主役は時計と動くビジュアル
- 操作要素を常時目立たせず、鑑賞を妨げない
- レトロ感は持たせつつ、既存のDVDロゴは模倣しない
- 縦画面と横画面の両方で成立させる

## 8. 実装方針

- 1機能を小さな単位に分け、実装・テスト・レビューを繰り返す
- Dartの言語機能を採用した理由を説明できる状態にする
- AIが生成したコードも、動作と責務を確認してから採用する
- 依存パッケージは必要性を説明できるものだけ追加する
- 重要な技術判断は`docs/decisions/`へ記録する
